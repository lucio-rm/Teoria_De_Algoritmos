\section{Analizando el Algoritmo}

Para analizar el algoritmo propuesto anteriormente, se puede ocurrir la manera de poner un ejemplo para analizar el comportamiento:
Siendo monedas = [1, 3, 4, 9, 6, 2]
\begin{enumerate}
	\item Turno de Sophia, ella sólo ve el par [1, 2] y agarra la moneda de mayor valor (el 2). Le toca ahora a Mateo, par [1, 6] y Sophia elige por él la moneda de valor 1. Sophia de vuelta [3, 6] elige el 6. Mateo [3, 9], suma 3. Sophia [4, 9] elige la moneda de valor 9. A Mateo finalmente le toca la moneda de valor 4. No quedan más monedas para elegir.
	\item Entonces, si se suman los valores de todas las monedas seleccionadas para cada uno: Puntos de Sophia = 2 + 6 + 9 = 17. Puntos de Mateo = 1 + 3 + 4 = 8. 
	\item Sophia gana.
\end{enumerate}

Se puede analizar el algoritmo implementado de varias formas, que vamos a estar explicando a continuación. Entre ellas, se va a hablar de la complejidad temporal y espacial algorítmica del algoritmo, el por qué tiene esos valores y si es posible mejorarla.

También se habla de la optimalidad del algoritmo, anteriormente se hizo una breve presentación de ésta la cual ahora se va a explayar más y se va a demostrar matemáticamente por el método inductivo.

Por último se van a realizar experimentos sobre el mismo algoritmo, poniendolo sobre arreglos de distintos tamaños para hacer mediciones de tiempo distintos.


\subsection{Complejidad}

Cuando se habla de \textit{complejidad algorítmica},


La complejidad del algoritmo diseñado para representar la sesión de juego de Sophia y Mateo es de $\mathcal{O}(n)$, esto debido a que se recorre todo el arreglo y por cada iteración lo único que se hace es comparar el elemento del principio con el del final, en basea eso y segun de quien sea el turno, se elige el más alto o el más bajo. Por cada pasada el arreglo se achica por izquierda o por derecha según se elija un elemento.

Una demostracion de esto seria:
\begin{itemize}
    \item Comparar \verb|monedas[inicio]| con \verb|monedas[fin]| es $\mathcal{O}(1)$.
    \item Elegir el mayor o el menor según el turno es $\mathcal{O}(1)$.
    \item Mover los punteros de \verb|inicio| y \verb|fin| sumando o restando es $\mathcal{O}(1)$.
\end{itemize}

Todo esto termina derivando en una ecuación de recurrencia
\begin{equation*} 
    \mathcal{T}(n) = \sum_{i=1}^{n-1} \mathcal{O}(1) = \mathcal{O}(n)
\end{equation*}

Que un algoritmo sea \textit{óptimo} significa que para cualquier caso o ejemplo de ejecución del problema, devuelva la mejor solución posible. Cuando se habla de algoritmos \textit{greedy}, su demostración de que sean óptimos puede ser un tanto difícil. Una vez demostrada y habiendo justificado que sea óptimo, se puede asumir que el mismo algoritmo lleva una de las mejores soluciones de ''manera'' greedy.

Las demostraciones matemáticas son las mas concisas cuando hablamos de optimalidad, a continuación se va a realizar la demostración por \textbf{método inductivo}. Va a consistir de 3 pasos: proponer el caso base, proponer el caso inductivo y demostrar que se cumple en todo momento.

Para el caso base, se puede proponer el conjunto de monedas de una sola: [$c_i$] con $c_i > 0$. Pero como Sophia siempre va a empezar, va a agarrar la que queda y para todo $c_i$ va a ser mayor a los puntos sumados por Mateo, que son = 0.

Entonces se propone el caso base con $M_1$ = [$c_i$, $c_j$], $c_i \ge c_j > 0$
